# M6 performance comparison: Bitsmith vs Chisels & Bits

[English](#english) | [Français](#français)

---

## English

### Setup

- Same machine, same settings for both mods: Minecraft 1.21.1, NeoForge 21.1.259, 1280x720,
  render distance 12, no frame cap, VSync off, Fancy graphics, smooth lighting, Spark installed
  with its background profiler off.
- Chisels & Bits 21.1.33. Bitsmith is also loaded in the Chisels & Bits run (development runs
  always load it) but has no block in the scene.
- Scene (`./gradlew runClientBench` / `runClientBenchCnb`): eight blocks of different materials,
  each carved with the mod's **own chisel** (16 single bits each), cloned into 2000 carved blocks
  (40 x 5 x 10). Control scene: the same volume of plain stone.
- Scenes recorded 10 s each: S1 static view, S2 continuous carving (a stroke every 4 ticks),
  S3 coming back after the chunks were unloaded, S4 flying over the scene.
- **3 valid runs per mod, alternated**, medians below. One Bitsmith run was discarded (its scene
  did not build: the eighth reference block was empty) and replaced. Another Minecraft client was
  running on the machine during all runs, so absolute FPS are noisy; compare the two mods, not the
  absolute values.

### Results (medians of 3 runs)

| Scene | Metric | Bitsmith | Chisels & Bits |
|---|---|---|---|
| S1 static view | average fps | 1446 | 1267 |
| | 1 % low fps | 521 | 333 |
| | worst frame | 9.7 ms | 38.9 ms |
| | ratio to the stone control (same run) | 1.02 | 0.97 |
| S2 continuous carving | average fps | 1445 | 1215 |
| | 1 % low fps | **406** | 275 |
| | worst frame | **9.6 ms** | 27.4 ms |
| | server tick, average / worst | 4.34 / 6.88 ms | 4.50 / 6.75 ms |
| S3 chunks loading back | average fps | 1435 | 847 |
| | 1 % low fps | **312** | 32 |
| | worst frame | **82.8 ms** | 527.2 ms |
| S4 flying over | average fps | 1300 | 1099 |
| | 1 % low fps | 406 | 307 |
| | worst frame | **15.6 ms** | 33.3 ms |

Bitsmith counters during S2 (medians): 163.8 µs of server time per stroke, 11.6 µs per tick to
apply the batched edits, 119.4 µs per mesh built in game, **exactly one section rebuild asked per
stroke** (43 strokes, 43 rebuilds), 0 resync.

### Reading

- **Static scenes**: both mods put carvings in the chunk mesh, so a still view of 2000 carved
  blocks costs about the same as plain stone for both. Differences here are within the noise.
- **Where Chisels & Bits stutters, Bitsmith does not**: coming back to a build is the clearest
  case (1 % low 312 fps vs 32 fps, worst frame 83 ms vs 527 ms, about six times shorter), then
  carving (1 % low +48 %, worst frame three times shorter) and flying over (worst frame halved).
- Server tick times are similar at this scale: the integrated server's own baseline (about 4 ms)
  dominates. Bitsmith's own server cost is under 0.1 ms per tick at the measured stroke rate.

### Goals of the specification

| Goal | Target | Measured | Status |
|---|---|---|---|
| P1 | static scene at least 90 % of vanilla | 102 % (median, per run 96 % to 122 %) | Met |
| P2 | no per frame cost for static carvings | no block entity renderer, no shape work per frame; S1 equal to the stone control | Met |
| P3 | no frame above 16.7 ms while carving (revised, see the specification) | worst frame 9.6 ms (median of 3 runs; 9.3 to 26.1 ms across runs) | Met in 2 of 3 runs, median met; one run had a 26.1 ms frame |
| P4 | one section rebuild per edit | 43 rebuilds for 43 strokes | Met |
| P5 | one rebuild per section on chunk load | by design (no per block update on load); chunk load hitch 6x shorter than Chisels & Bits | Met by design, rebuild count not measured directly |
| P6 | mesh under 0.3 ms | 0.12 ms in game, 0.27 ms worst core case | Met |
| P7 | single bit edit under 128 bytes | 37 bytes (game test) | Met |
| P8 | two material block at most 600 bytes | 520 bytes, identical carvings shared | Met |
| P9 | under 1 ms per tick for Bitsmith while carving | about 0.07 ms per tick at full stroke rate, 0.66 ms at the server's 4 strokes per tick cap | Met |
| P10 | no crash, desync or lost bits in multiplayer | 10 minute soak: 12000 bot operations, 0 desync, 0 exception (`2026-10-15-soak.md`) | Met for 10 minutes; the 1 hour run is still to do |

Spark profiles of each run (client static view, server while carving) are saved as files in
`run-bench*/config/spark/`; they were never uploaded.

## Français

### Conditions

- Même machine, mêmes réglages pour les deux mods : Minecraft 1.21.1, NeoForge 21.1.259, 1280x720,
  distance de rendu 12, FPS non limités, VSync désactivée, graphismes Détaillés, éclairage lissé,
  Spark installé avec son profileur d'arrière-plan désactivé.
- Chisels & Bits 21.1.33. Bitsmith est aussi chargé dans le run Chisels & Bits (les runs de
  développement le chargent toujours) mais n'a aucun bloc dans la scène.
- Scène (`./gradlew runClientBench` / `runClientBenchCnb`) : huit blocs de matériaux différents,
  chacun ciselé avec le **ciseau du mod lui-même** (16 bits seuls chacun), clonés en 2000 blocs
  ciselés (40 x 5 x 10). Scène témoin : le même volume en pierre pleine.
- Scènes enregistrées 10 s chacune : S1 vue statique, S2 ciselage continu (un coup tous les 4
  ticks), S3 retour après déchargement des chunks, S4 survol de la scène.
- **3 runs valides par mod, en alternance**, médianes ci-dessous. Un run Bitsmith a été écarté (sa
  scène ne s'est pas construite : le huitième bloc de référence était vide) et remplacé. Un autre
  client Minecraft tournait sur la machine pendant tous les runs : les FPS absolus sont bruités ;
  comparer les deux mods, pas les valeurs absolues.

reconstruction de section demandée par coup** (43 coups, 43 reconstructions), 0 resynchronisation.

### Lecture

- **Scènes statiques** : les deux mods mettent les sculptures dans le maillage des chunks, donc
  une vue fixe de 2000 blocs ciselés coûte à peu près comme de la pierre pleine pour les deux. Les
  écarts ici sont dans le bruit.
- **Là où Chisels & Bits saccade, Bitsmith non** : le retour vers une construction est le cas le
  plus net (1 % bas 312 FPS contre 32, pire image 83 ms contre 527 ms, environ six fois plus
  courte), puis le ciselage (1 % bas +48 %, pire image trois fois plus courte) et le survol (pire
  image divisée par deux).
- Les ticks serveur sont proches à cette échelle : la base du serveur intégré (environ 4 ms)
  domine. Le coût serveur propre à Bitsmith est sous 0,1 ms par tick au rythme mesuré.
